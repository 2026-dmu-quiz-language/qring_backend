DEPLOYMENT GUIDE

Qring 배포 가이드

Docker × Cloudflare Tunnel × 온프레미스 PC

한 줄 요약 배포 다이어그램 Docker 컨테이너 Cloudflare 셋업 실제 배포 명령 다른 PC로 이전 시크릿 관리 프론트엔드 통합 운영 팁

📌 한 줄 요약

Qring 백엔드는 특정 PC(온프레미스)에서 Docker Compose로 실행되며, 외부 접근은 공인 IP나 포트포워딩 없이 Cloudflare Tunnel을 통해 q-ring.app 도메인으로 노출됩니다.

핵심 특징: 운영 PC에 클라우드 비용 없음 · 공인 IP 없음 · 방화벽/공유기 설정 변경 없음. git clone → 시크릿 파일 2개 복사 → docker compose up -d --build 한 줄로 끝.

사용자 단말 → Cloudflare → 온프레미스 PC 내부 Docker 컨테이너까지의 경로.

왜 공인 IP가 필요 없나? cloudflared는 PC 내부에서 Cloudflare로 아웃바운드 QUIC 연결을 먼저 맺어둡니다. 사용자 요청은 이 기존 연결을 통해 거꾸로 흘러 들어오기 때문에, NAT/방화벽 너머에 있어도 외부에서 접근 가능합니다.

🐳 Docker Compose 컨테이너 구성

docker-compose.yml에 정의된 3개 서비스가 같은 도커 네트워크 안에서 서로 서비스명으로 통신합니다.

🍃 backend

Spring Boot 3 + Java 21. Dockerfile의 multi-stage 빌드로 app.jar 생성 → 실행.

qring-backend · 호스트 :8080

🐬 mysql

MySQL 8.0. utf8mb4 설정. data.sql 시드 자동 적재. 볼륨으로 데이터 영속화.

qring-mysql · 호스트 :3307 → 컨테이너 :3306

🔌 cloudflared

공식 cloudflare/cloudflared:latest 이미지. config.yml + credentials.json 마운트.

qring-cloudflared · 외부 포트 노출 없음

의존 순서 (depends_on)

  • mysql — healthcheck 통과 후 backend 시작
  • backend — mysql 준비된 후 시작 → cloudflared 시작 트리거
  • cloudflared — backend 시작 후 터널 연결

네트워크 통신 매핑

☁️ Cloudflare 셋업 (일회성)

한 번만 해두면 이후로는 손댈 일이 없는 셋업입니다.

① 도메인 위임

  1. name.com에서 q-ring.app 구매
  2. Cloudflare 대시보드에 도메인 추가 → 네임서버 2개 발급
  3. name.com의 Nameservers를 Cloudflare 것으로 교체 → 전파 대기

② Tunnel 생성

# 한 번만 (개발 PC에서 수행)
cloudflared tunnel login   # 브라우저로 인증 → cert.pem 발급
cloudflared tunnel create qring-backend
# → 터널 UUID + ~/.cloudflared/<UUID>.json 자격증명 생성

③ DNS 라우팅

cloudflared tunnel route dns --overwrite-dns 5033c8b4-3c13-4163-9586-015d2b0fcab5 q-ring.app
# → Cloudflare DNS에 CNAME q-ring.app → <UUID>.cfargotunnel.com 자동 등록

④ 자격증명을 프로젝트로 이동

~/.cloudflared/<UUID>.json 파일을 프로젝트의 cloudflared/credentials.json으로 복사. (도커 볼륨 마운트용)

주의: 이 4단계는 이미 완료된 상태입니다. 다른 PC로 옮길 때는 다시 할 필요 없음 — Tunnel 자체는 Cloudflare에 등록되어 있고, credentials.json만 가져가면 어느 PC에서든 같은 터널을 띄울 수 있습니다.

🚀 실제 배포 명령

컨테이너 셋업이 끝났다면 매번 이 명령들만 씁니다.

최초 기동

# 백엔드 + DB + cloudflared 전체 기동 (백그라운드)
docker compose up -d --build

# 로그 실시간 확인 (Ctrl+C로 빠져나옴, 컨테이너는 계속 동작)
docker compose logs -f

# 특정 컨테이너만
docker logs -f qring-backend
docker logs -f qring-cloudflared

코드 수정 후 재배포

# 백엔드 코드만 변경한 경우 → backend만 재빌드
docker compose up -d --build backend

# docker-compose.yml 자체를 수정한 경우 → 전체 재시작
docker compose down
docker compose up -d --build

정지 / 정리

# 컨테이너만 정지 (데이터 보존)
docker compose stop

# 컨테이너 + 네트워크 제거 (볼륨/데이터는 유지)
docker compose down

# DB까지 완전 초기화 (data.sql이 다시 적재됨)
docker compose down -v

정상 동작 확인

  • docker ps → 3개 컨테이너 모두 Up 상태
  • docker logs qring-cloudflared에 Registered tunnel connection 4줄
  • 브라우저로 https://q-ring.app 접속 → 환영 페이지 표시

💻 다른 PC로 옮기는 방법

운영 PC를 교체하거나 팀원에게 인계할 때, 클라우드 마이그레이션 없이 새 PC에서 한 번에 띄울 수 있습니다.

  1. 새 PC에 사전 설치
    • Docker Desktop (또는 Docker Engine + Docker Compose)
    • Git
  2. 코드 받기 
    git clone https://github.com/2026-dmu-quiz-language/qring_backend.git
cd qring_backend
  3. 시크릿 파일 2개 복사 (USB 또는 안전한 채널로)
    • .env → 프로젝트 루트
    • cloudflared/credentials.json → cloudflared/ 폴더
  4. 기동 
    docker compose up -d --build
  5. 완료 — 새 PC에서 자동으로 같은 q-ring.app 도메인이 동작.
    (기존 PC의 cloudflared는 미리 종료해두는 게 좋음 — 동시 운영 시 트래픽이 양쪽으로 분산됨)
도메인 / Cloudflare 설정 변경 불필요: 터널 UUID와 credentials.json만 같으면, 어느 PC에서 cloudflared가 돌든 Cloudflare는 동일한 터널로 인식합니다.

🔐 시크릿 관리

git에 절대 올라가면 안 되는 파일들과 그 관리 방법입니다.

파일위치내용git ignore
.env 프로젝트 루트 DB 비번 · JWT secret · 메일 계정 · OAuth 키 ✅ (.env 패턴)
credentials.json cloudflared/ Cloudflare Tunnel 자격증명 (UUID + secret) ✅ (cloudflared/credentials.json)
config.yml cloudflared/ 터널 ID + ingress 라우팅 (시크릿 아님) ❌ (커밋 OK)
현 시점 .gitignore: .env, .env.local, *.env, cloudflared/credentials.json 차단 중. 새 시크릿 파일 추가 시 반드시 .gitignore에 등록할 것.

🧩 프론트엔드 통합 (Expo Web)

현재는 백엔드만 배포된 상태입니다. 프론트 코드가 들어오면 같은 q-ring.app 도메인 하나로 통합 운영할 수 있게 자리가 잡혀 있습니다.

📂 현재 준비된 것

  • frontend/ 폴더 (비어있음) — 프론트 소스가 들어올 자리
  • frontend/README.md — 통합 절차 + Dockerfile / nginx.conf 예시 전체 수록
  • docker-compose.yml에 frontend 서비스 블록 주석 처리해둠 — 활성화 1줄

🔧 통합 방식 (reviewall과 동일)

프론트 빌드 결과물(정적 파일)을 nginx 컨테이너로 서빙하고, nginx가 /api 등 백엔드 경로만 backend:8080으로 프록시합니다. 모바일/웹 모두 같은 q-ring.app 도메인으로 백엔드 호출.

🚀 프론트 코드 받았을 때 활성화 4단계

  1. 소스 배치 — 프론트 코드를 frontend/ 안에 두기 (frontend/package.json이 보이도록). Dockerfile + nginx.conf는 frontend/README.md의 예시 그대로 사용
  2. docker-compose.yml 활성화 — frontend 서비스 블록 주석 해제
  3. cloudflared 라우팅 변경 — cloudflared/config.yml 에서 http://backend:8080 → http://frontend:80 한 줄 수정
  4. 기동 — docker compose up -d --build
결과: https://q-ring.app 접속 시 웹앱이 보이고, 웹앱 내부의 /api/* 호출은 자동으로 백엔드로 프록시됨. 모바일 앱은 코드 변경 없이 그대로 동작.
💡 권장 정리: 백엔드 컨트롤러 경로가 현재 /api/v1/auth/* (인증) 와 /contentList, /chat, /questionResult, /dashboard/* (학습)로 섞여 있습니다. 프론트 통합 전에 모두 /api/v1/* 아래로 통일하면 nginx.conf가 훨씬 깔끔해집니다.

🛟 운영 팁

도메인 라우팅이 안 될 때

  1. Cloudflare 대시보드 → DNS → Records에서 q-ring.app CNAME이 올바른 터널 UUID(5033c8b4-...)를 가리키는지 확인
  2. cloudflared tunnel list로 터널 존재 확인
  3. 컨테이너 로그에 Registered tunnel connection 4줄 떴는지 확인

백엔드 코드는 바뀌었는데 적용 안 됨

  • docker compose up -d만으로는 이미지 재빌드가 안 됨. --build 플래그 필수
  • 확실히 갈아엎으려면 docker compose down && docker compose up -d --build

DB 시드 데이터 갱신

  • src/main/resources/data.sql은 INSERT IGNORE 기반 — 기존 row 있으면 건너뜀
  • 완전 초기화: docker compose down -v (볼륨 삭제) 후 재기동

cloudflared 버전 업데이트

# 이미지 최신화
docker compose pull cloudflared
docker compose up -d cloudflared

PC 재부팅 후 자동 시작

docker-compose.yml의 모든 서비스에 restart: unless-stopped가 설정되어 있어, Docker Desktop이 부팅 시 자동 시작되도록 설정만 해두면 PC 재부팅 후에도 자동 복구됩니다.
